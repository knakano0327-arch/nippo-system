## 1. テスト方針

### 1.1 目的

営業日報システムの品質を保証するため、各機能が要件定義・画面定義書・API仕様書に従って正しく動作することを確認する。

### 1.2 テストレベル

| レベル | 内容 | 主な担当 |
|--------|------|---------|
| 単体テスト | モデル・バリデーション・ビジネスロジック単位の検証 | 開発者 |
| APIテスト（結合テスト） | エンドポイント単位の入出力・権限・エラー処理の検証 | 開発者 |
| 画面テスト（E2Eテスト） | ブラウザ操作を通じた画面遷移・操作フローの検証 | QA担当 |
| 非機能テスト | 性能・セキュリティの検証 | 開発者・QA担当 |

### 1.3 合否判定基準

- **合格（Pass）:** 期待結果と実際の結果が完全に一致する
- **不合格（Fail）:** 期待結果と実際の結果が一致しない
- **対象外（N/A）:** テスト環境の制約等により実施不可

## 2. テスト範囲と種別

### 2.1 対象機能

| 機能カテゴリ | 対象 |
|------------|------|
| 認証 | ログイン・ログアウト・トークン管理 |
| 日報管理 | 作成・編集・提出・詳細表示・削除 |
| 訪問記録管理 | 複数行の追加・編集・削除 |
| コメント管理 | 上長によるコメント投稿・編集・削除 |
| ステータス管理 | 下書き→提出済み→確認済みの遷移 |
| 権限制御 | 営業・上長・管理者ごとのアクセス制御 |
| 顧客マスタ管理 | CRUD操作 |
| 営業マスタ管理 | CRUD操作 |

### 2.2 対象外

- 外部システム連携（本システムにおいては存在しない）
- メール通知機能（将来拡張予定として対象外）
